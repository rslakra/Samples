# Node.js Components

Small, self-contained CommonJS scripts that demonstrate Node.js core modules: custom
modules, `os`, `path`, `fs` (callbacks), `fs.promises`, and streams.

There is **no build step and no dependencies** — everything uses Node's built-in modules.

## Requirements

- Node.js 18+ (`core/builtin.js` uses `os.availableParallelism()`, added in 18.4; it is
  guarded with `?.` so older versions still run)

```bash
node -v
```

## Project layout

```
nodejs-components/
├── Makefile
├── README.md
├── server.js            # entry point — uses the local math module
├── core/
│   ├── math.js          # exported add / subtract / multiply / divide
│   ├── builtin.js       # os + path info, CPU cores, cgroup CPU quota
│   ├── file.js          # fs.readFile / fs.writeFile with callbacks
│   ├── promise.js       # fs.promises read / unlink / write / append
│   └── stream.js        # createReadStream -> createWriteStream, chunk by chunk
└── data/
    ├── small.txt        # input for file.js and promise.js
    ├── large.txt        # input for stream.js
    ├── reply.txt        # generated by file.js
    ├── promises.txt     # generated by promise.js
    └── large-write.txt  # generated by stream.js
```

## Build

Nothing to build. The scripts are plain CommonJS (`require` / `module.exports`) and run
directly on Node.

## Run

### With make (recommended)

```bash
cd Samples/Node.js/nodejs-components

make help      # list all targets
make check     # verify Node.js is installed and new enough
make start     # server.js — math module demo
make builtin   # core/builtin.js
make file      # core/file.js
make promise   # core/promise.js
make stream    # core/stream.js
make all       # run every demo in order
make clean     # delete generated data files
make reset     # clean + restore data/small.txt
```

### With node directly

```bash
cd Samples/Node.js/nodejs-components

node server.js
node core/builtin.js
node core/file.js
node core/promise.js
node core/stream.js
```

All scripts resolve paths from `__dirname`, so they work from any working directory as
long as `core/` stays one level under the project root.

## What each script does

| Script | Demonstrates | Output |
| --- | --- | --- |
| `server.js` | Importing a local module and destructuring its exports | Math results on stdout |
| `core/math.js` | Two export styles (`module.exports` vs `exports.x`) | — |
| `core/builtin.js` | `os` (home dir, type, memory, CPUs), `path.parse`, `__dirname` / `__filename`, cgroup CPU quota | System details on stdout |
| `core/file.js` | Callback-based `fs.readFile` / `fs.writeFile`, `process.on('uncaughtException')` | `data/reply.txt` |
| `core/promise.js` | `async/await` with `fs.promises`: read, unlink, write, append, read back | `data/promises.txt` |
| `core/stream.js` | `createReadStream` / `createWriteStream` and the `data` event, chunk counting | `data/large-write.txt` |

## Gotchas

- **`core/promise.js` deletes `data/small.txt`** (it calls `fsPromises.unlink`). After one
  run, `core/file.js` and a second run of `promise.js` fail with `ENOENT`.
  Restore it with `make data` (or `make reset`), or `git checkout data/small.txt`.
- `core/stream.js` prints every chunk of `data/large.txt`, so expect a lot of output.
- `core/builtin.js` reads `/sys/fs/cgroup/cpu.max` to detect a container CPU limit. That
  path does not exist on macOS, and the failure is swallowed by design.
